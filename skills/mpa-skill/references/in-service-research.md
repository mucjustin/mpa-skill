# In-Service Research: workplace problems, insider ethics and dual output

何时查阅：学生想把本职工作中的问题变成选题；研究对象、数据或访谈对象来自学生本单位或本系统；需要对材料脱敏；或希望同一项研究同时产出论文和工作中可用的政策建议报告。配合 [case research](case-research.md)、[evidence protocol](evidence-protocol.md) 与 [research contract](mpa-research-contract.md) 使用。

大多数 MPA 学生是在职公务员或公共部门人员。他们的优势是熟悉情境、能接触一线材料；风险是身在其中、身份敏感、材料可能受保密约束。本文件只补充这些在职场景特有的规则，不替代学校、导师、伦理审查和保密规定——这些规定始终优先 (current programme, supervisor, ethics and confidentiality rules override this file)。

## 1. 工作问题 → 研究选题

学生通常从一句工作中的困扰出发（如“网格员任务太重，落实走样”）。按四层拆解，每层都要学生确认，不替学生决定：

| 层次 | 要回答的问题 | 常见错误 |
|---|---|---|
| 工作现象 | 具体发生了什么？在哪个单位、什么时间范围、涉及谁？ | 用口号或结论代替现象（“基层负担重”） |
| 公共管理问题 | 这个现象背后是什么公共问题？影响谁的公共利益？ | 停留在本单位内部管理技巧，缺公共性 |
| 研究问题 | 一个可以用证据回答的问题（为什么／如何／在什么条件下） | 问题太大（“如何提升基层治理能力”）或已有答案 |
| 理论对话 | 可能对话的理论及其可观察含义（从 [mpa-knowledge.md](mpa-knowledge.md) 理论地图选择） | 先选理论再找问题；理论只作标签 |

给出 2–3 个**真正不同**的候选题目，用下表比较，并说明推荐与放弃的理由：

| 维度 | 检查点 |
|---|---|
| 证据可得性 | 需要哪些材料？学生合法能拿到吗？是否需要单位批准？ |
| 可毕业性 | 题目范围、方法与时间是否匹配学位要求和剩余学期？ |
| 身份风险 | 研究会不会评价自己负责的工作、上级或同事？结论不利时能否如实写？ |
| 保密约束 | 关键材料是否属于内部、敏感或涉密信息？能否以公开或脱敏形式使用？ |
| 工作关联 | 结论能否反馈到工作中？是否有明确的使用者（决策者、部门）？ |
| 理论空间 | 是否不止于经验总结，能检验、修正或限定某个理论命题？ |

缺少事实时输出“待确认事项”，不编造单位、数据或事件。题目确定后，把研究主线进度写入工作台：`progress "<workspace>" --set problem=established`。

## 2. 局内人研究检查 (insider research)

研究本单位、本系统或自己参与的项目时，在收集材料前逐项检查，并把结论写入研究设计的“研究伦理与局限”部分：

- **角色冲突**：学生同时是研究者和当事人。评价自己负责的项目时，明确如何防止“为自己说好话”（如引入外部材料、请无利害关系者复核、主动寻找反面证据）。
- **权力关系**：上级访谈下级、管理者调查服务对象时，对方可能不敢说真话。说明如何降低压力（匿名、由第三方发放问卷、不在工作场所访谈、明确拒绝不影响工作）。
- **知情同意**：同事和服务对象有权知道这是学位研究、材料如何使用、可以拒绝。不把工作中偶然听到的话当作访谈材料。
- **材料分级**：区分公开材料、内部可引用材料、内部不可引用材料、涉密材料。**涉密材料不进入研究，也不交给 AI 处理**；内部材料按单位规定取得许可后再用。
- **反面证据与沉默群体**：局内人容易只看到“上面”和“自己人”的视角。列出没有发声的群体（如被服务群众、基层一线、反对者），并说明如何补充或作为局限披露。
- **结论不利时**：提前想好如果研究发现本单位做法有问题，如何如实呈现、是否需要脱敏或调整发表范围。不得为了“好看”删改证据。

任一项无法解决时，作为 `RISK` 记录并提示学生与导师商量，必要时调整题目。

## 3. 脱敏工作流

把访谈记录、内部材料或初稿交给 AI、导师或同学之前，先在本地脱敏。工作台提供离线命令，不联网、不上传：

1. 学生编写一个只保存在本地的术语表（UTF-8 文本，每行一个原词，或 `原词=替代词`，如 `城东街道=A街道`）。
2. 对文本文件脱敏：`python "<skill-root>/scripts/mpa_evidence.py" redact "<transcript.md>" --redact-terms "<terms.txt>" --output "<transcript.redacted.md>"`。
3. 导出证据矩阵时同样脱敏：`export "<workspace>" --output "<matrix.md>" --redact-terms "<terms.txt>"`。
4. 自动规则会替换身份证号、手机号、固定电话、邮箱和公文文号，但**这只是兜底，不是保证**。人名、单位名、地名、职务和可推断身份的细节必须由学生在术语表中列出，并在分享前人工通读。

术语表本身就是敏感信息：不提交到仓库，不发给 AI。脱敏不改变原始证据库；原始材料仍按 [evidence protocol](evidence-protocol.md) 的隐私规则保管。

## 4. 一份研究，两种产出 (dual output)

在职学生的研究最好同时服务于学位和工作。在论文证据与分析被接受后，可以从同一证据库派生一份面向工作的产出（政策建议报告、调研报告或内部参考），规则如下：

- **同源**：两份文稿使用同一套已登记的论断与证据编号；工作报告中的每条判断和建议都能回链到 C/E 编号。
- **不加码**：工作报告不能出现论文中没有证据支撑的结论，也不能因为读者是领导而删除不利证据或把推断写成事实。
- **体例不同**：论文强调问题、理论、方法与局限；工作报告强调结论先行、可执行建议、责任主体、成本与风险（参见 [templates](templates.md) 政策备忘录骨架）。
- **保密与署名**：工作报告的使用范围、是否需要脱敏、能否引用内部材料，以单位规定为准；论文中涉及的内部材料按第 2 节分级处理。
- **AI 使用披露**：两份文稿都按 [AI-use disclosure](aigc-disclosure.md) 如实说明 AI 参与情况。

## 5. 碎片时间与进度续接

在职学生常常每次只有半小时。每次会话结束前，用 `progress` 记录主线各环节状态和下一步任务；下次开始时先运行 `progress "<workspace>"`，按 `suggested_next` 给出一张 30 分钟左右能完成的任务卡，而不是重新从头规划。没有本地工具时，在交付物末尾用同样的“主线状态 + 下一步”格式手写进度。
