# Routing

Choose the minimum sufficient route from capabilities actually available in the current Codex environment. Route coverage: course → case analysis → case competition entry → policy memo → literature → research design → fieldwork → data analysis → thesis → defence → non-MPA to MPA conversion.

| Route | Intended output | Sequence rule |
|---|---|---|
| course | notes, revision map, assignment inputs | inventory and read the agreed corpus before synthesis |
| case analysis | applied case brief | establish actors, institutions, mechanisms, outcomes, and alternatives before lessons |
| case competition entry | competition-grade entry plan | read [case competition rules](mpa-case-competition.md), verify the current-year notice, and confirm fieldwork evidence and theory applicability before drafting |
| policy memo | decision-ready memo | define audience and options before recommendation |
| literature | source set, source cards, literature map | tie search and reading to the applied question; verify identity before citation |
| research design | proposal or design memo | define problem, question, scope, framework, evidence, and method before prose |
| fieldwork | sampling and collection package | resolve ethics, access, instrument mapping, and data protection before collection |
| data analysis | reproducible analysis and report | audit data quality and preserve raw data before transformation or modelling |
| thesis | evidence-grounded chapters | accept evidence and analysis before drafting or polishing |
| defence | presentation and challenge preparation | stabilize thesis claims before narrative and visual production |
| non-MPA to MPA conversion | re-anchored MPA research design | audit source-data consistency and remap the public problem, stakeholders, and theory through the MPA Research Spine before rewriting; when the user supplies raw data, run the data route before drafting; rewording alone is not conversion |
| theory grounding | theory-map reference | select theory before evidence design; confirm paper-type fit |
| china-context check | china-contexts reference | verify governance context and constraints before conclusion |

For cross-route work, order only the needed phases by dependency. A common sequence is intake → theory grounding → course/case assets → literature → research design → fieldwork → data → thinking check → thesis → defence. Theory grounding reads [theory map](mpa-theory-map.md) before evidence design; thinking check runs [thinking checklist](mpa-thinking-checklist.md) before prose acceptance.

Offer Zotero or Obsidian integration once in the route confirmation when a substantive research task states no preference; write nothing to either before the user confirms.

For case competition entries, plan the three-document structure (案例正文, 案例分析报告, 调研报告), fieldwork evidence, and theory applicability before any drafting; course case-analysis assignments use the research contract without competition deliverables.

Use [MPA deliverables](mpa-deliverables.md) to shape the output and [MPA research contract](mpa-research-contract.md) to gate claims. Read [case competition rules](mpa-case-competition.md) before case-competition entry planning. Read [dependencies](dependencies.md) before selecting specialist tools. Read [real-data workflow](real-data-workflow.md) before rerunning analysis on user-supplied data. Read [local office editing](local-office-editing.md) before batch writes to local Word documents. Read [theory map](mpa-theory-map.md) before research design or thesis drafting; read [china contexts](mpa-china-contexts.md) before case analysis or policy recommendations; read [thinking checklist](mpa-thinking-checklist.md) before each draft acceptance; read [course map](mpa-course-map.md) before course assignments or study planning. Do not invoke this controller merely because a request mentions a thesis, spreadsheet, Zotero, Obsidian, teaching, or writing without MPA context.
