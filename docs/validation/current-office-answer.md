当前应标记为 **`STATE_UNKNOWN`（写入状态未知）并停止编辑**。连接断开不代表写入失败；现在无法检查，也不能判断是否保存。不要重放上次请求、回滚或宣称完成。已有修改授权仍然有效，恢复后无需重复申请。

保留已知的 `doc_id`、上次请求使用的版本、目标单元格上下文和修改内容；缺失的信息如实标记，不补造。

待 `inspect_document` 恢复后，按以下顺序处理：

1. **重新读取同一 `doc_id`。** 获取当前 `revision` 和文本，结合表格上下文重新定位目标，要求唯一匹配；不要复用中断前的位置或版本。
2. **判断目标位置的实际状态：**

   | 当前目标内容 | 状态与处理 |
   |---|---|
   | 只有“预算100万元” | 未应用，可以准备一次替换 |
   | 只有“预算120万元” | 已应用，不再写入，进入验收 |
   | 新旧文本并存 | 检查是否存在重复或部分应用；不能唯一解释时停止 |
   | 两者都没有，或无法唯一定位 | 状态仍未知或存在冲突，先查明，不覆盖 |

   判断限于授权修改的目标单元格；其他位置合法出现的相同文字不应一并替换。

3. **仅对确认未应用的目标恢复写入。** 使用刚读取的 `revision` 作为 `expected_revision`，按工具实际支持的 `edits` 格式，将目标单元格中的“预算100万元”替换为“预算120万元”。题目没有提供 `edits` 的结构，不能凭空编造参数格式。若版本不匹配，重新检查、重新判断；不能只换版本后盲目重放。
4. **检查返回并再次读取。** 核对 `changed_count` 是否符合本次单项修改的预期，并记录 `saved_revision`。随后再次调用 `inspect_document`，确认目标新文本存在、旧文本消失，并比对当前版本与 `saved_revision`。若版本又发生变化，应检查是否有后续编辑，不能直接认定验收通过。若再次断线且无法读取，重新进入 `STATE_UNKNOWN`。

验收报告应列明目标 `doc_id`、实际修改计数及版本证据。若恢复时发现修改已经保存，应说明“此前写入已落地，本次未重复修改”。

当前合约只有文本检查能力，因此只能完成文本和版本验收，无法确认 Word 表格的排版、样式或渲染效果；也不应虚构额外的保存、撤销或重开命令。
